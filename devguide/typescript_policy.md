# TypeScript component engineering

Accepted under uibcdf/molsyssuite#199 for `typescript-package` members. This
capability consumes actual conformance, official starter, native quality and
generic-resource receiving behavior. It does not manufacture a Python package,
scientific runtime dependency or product/platform qualification.

## Source and tooling

Use a framework-independent ESM package with explicit public imports and
TypeScript declarations, canonical X.Y.Z versions and a complete committed npm
lock. npm is the development/build and private-consumer boundary; a component's
public distribution route remains separately selected. A private 0.0.0 source
placeholder is not a release. Match package/lock/tag identities for a release.

The initial baseline is Node 24, TypeScript 5.9.3 and Prettier 3.6.2. Pin actual
development tools and receive their lock identities. The qualified fixture uses
Node 24.22.1/npm 11.19.1; this is a selected execution, not proof for every future
Node version. Strict compilation, format checking, native node:test exits,
independent packed-consumer imports/declarations and relocated resource identity
are mandatory applicable checks. Keep browser, native providers, Python source
adapters, scientific behavior, performance and installed/public profiles separate.

`typescript_repository.py` inspects structural metadata and actual versioned
callers; it cannot establish that arbitrary owner commands have correct semantics.
`check-typescript-repository.yaml` executes the applicable native controls.
Use its immutable policy tag. A Python-only gate cannot qualify this capability.
Existing frozen Python gates keep their contracts and compatibility identities.

## Reporting and starter

Use `bootstrap_typescript.py` after the feature policy is published. Its default
CLI independently verifies the latest target and frozen vocabulary; admission
data cannot add a capability unknown to that snapshot. Render an empty stage and
review integration with existing source. Run npm ci, explicitly format the new
generated source, then receive its applicable checks. Do not replace an existing
component with a generated skeleton.

The official template uses administrative Python 3.14/stdlib for its offline
front matter/index validator, with an owning static Node guard resolver. Neither
is distributed as a Python library/runtime facade. A component may retain its
documented tested equivalent. The initial Node selector profile accepts one
regular `.test.mjs` module under tests/: the pinned compiler AST resolves a
node:test import and a top-level named static test call. Comments, unrelated
bindings, traversal, aliases and dynamic wrappers do not establish addressability.
Actual native execution and reviewed relevance remain independent requirements.

Common root/nested instructions, reporting lifecycle, resource-aware execution,
ownership, release notices and canonical-guide synchronization still apply.
Python adapter work follows its applicable Python boundary rules without turning
the frontend into a Python package. Adding a distributed Python companion needs
its own explicit capability, dependency and artifact receiving.

## Artifact and scientific boundaries

Use the [generic-resource profile](generic_resource_conda.md) for the initial
architecture-independent ESM/declaration payload. A prefix-layout probe is not
an original Conda archive, installation, browser/Qt or public proof. Publication
remains separately authorized and gated; no runtime Python or scientific suite
is added merely to fit a Python artifact adapter.

MolSysSketcher is a primary, active, incubating scientific component with two
equally important views: molecular representation/exploration and interaction
diagrams. It owns presentation, scene/visual layout and interaction lifecycle.
MolSysMT/RDKit/domain providers own chemistry, preparation, scientific results
and meanings. MolSysViewer retains its 3D/host boundary. Supplied references,
native receiving and live computation stay distinct. Keep exact mappings,
methods/versions/units/coverage and original assertions; production chemical
editing remains last. Admission qualifies none of the product delivery gates.
