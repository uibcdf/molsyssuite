# Discussions upkeep outline

Adapt this outline to the repository. Retain its actual category and label
vocabulary, existing links and substantive conversations.

1. **Purpose and entry:** link the actual Discussions area, local maintainer/triage
   owner and this guide's contributor reading route.
2. **Categories:** for each real category describe purpose, audience, information
   needed, useful examples/forms, owner and durable destination. Announcements,
   Ideas and Q&A are mandatory. Resource categories are individual optional
   suggestions; other purposeful local arrangements are welcome.
3. **Labels:** name the actual local facets, rationale, who applies them and how
   they relate to categories. Do not infer that issue kind/state labels exist as
   Discussion labels or impose one global vocabulary.
4. **Resource conversations:** search/reuse existing threads, cite sources with
   dates/versions, distinguish evidence from interpretation and update reviews.
   Keep substantive analysis in the conversation; link reproducible artifacts.
5. **Maintenance:** explain duplicate linking, useful answers, dated corrections
   and preserving ongoing/historical discussions without deleting their history.
6. **Concrete work:** open/update the owning issue when actionable; retain dated
   decisions and reasons in the owning issue/versioned record, with reciprocal
   links and a concrete revisit trigger for deferral.
7. **Authority:** follow normal disclosure, privacy and posting authorization.
   Reading alone grants no posting, subscriptions or scientific implementation.

Record observed configuration separately from desired configuration. A source
form or API category name does not prove rendered UI behavior. Review this guide
when categories, ownership, forms or local label meanings change.
