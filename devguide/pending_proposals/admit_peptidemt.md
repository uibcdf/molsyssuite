# Admit PeptideMT through the official registered-component route

**Reported:** 2026-10-27, explicit investigator authorization of W0–W4.
**Status:** Proposed registration awaiting central acceptance; no admission or
scientific implementation claimed.

## What

Register `uibcdf/peptidemt` as a primary `scientific-component`, `incubating`,
with `development-mode = active` and `capabilities = [python-package]`.

Codex implements the accepted scope but does not grant central acceptance.

## How

Add the member classification and canonical MolSysSuite-guide relationship.
Initialize ecosystem, CI and distribution reviews as pending against this
admission issue, with no platform, publication-access or runtime-adoption claim.
Record the observed absence of a Conda publisher at the existing design commit
and unknown optional archival evidence; do not introduce a publisher, DOI claim

After acceptance and publication on central main, use the official starter in
an empty temporary destination with the actual immutable policy and, when

the existing repository while preserving every scientific document and Git

The selected policy remains unchanged by this registration proposal.

## Why

PeptideMT's accepted increment-1 design evaluates external single-peptide
sequence proposals for predictive AMP compatibility and adverse hemolysis,
preserving evidence and reproducible selection. D35 and M1–M8 define the
scientific contract. The investigators have authorized W0 admission, followed
by W1–W4 only after W0 succeeds. This supplies a real governed entry point
without declaring the documentation repository an already admitted package.

## Ownership and exclusions

PeptideMT owns design intent/plan/execution relationships, occurrence mapping,
qualified evaluation attribution and action-specific selection. MolSysMT owns
molecular representation/manipulation. Macrel owns native features and both
classifiers. Support-library and MOLI ownership remains unchanged. No second
topology/chemistry engine or general scientific orchestration service is added.

Macrel 1.6.1 on Linux CPU/Python 3.14 is a qualification candidate. Both models
must actually execute; package/model identity, terms, fixtures and effective
resource limits must be recorded first. Engine-free tests cannot certify this
integration. Main-package Python support follows the suite baseline.

HydrAMP, increments 2/3, target-conditioned generation, new scientific models,
package publication and general development-issue creation remain excluded.
The sole authorized issue exception is this central admission theme.

2. Required central governance/index/dependency checks pass for the exact change;
