# Adopt optional Discussions suggestions and local upkeep routes

**Reported:** Existing issue #174; selected for Diego's second ten-issue batch on 2026-11-12.
**Status:** Central source/receiving prepared; publication, applicable hosted proof and guide delivery remain explicit below. Component-owned omissions remain pending.

## What

The existing Announcements/Ideas/Q&A baseline remains required. Datasets and Benchmarks, Literature and Resources, and Methods and Tools are individual optional suggestions; omitted suggestions require no exception. The maintained policy, central local guide, reusable outline, canonical guide and generated starter route explain category purposes/owners, actual labels/forms, resource reuse/sources/reviews, answers/duplicates/corrections, reciprocal issue/decision links and posting/privacy. Substantive scientific/resource discussion stays in its conversations. Current/default local-path observations and owner follow-ups are retained separately from guide delivery and UI configuration. MolI #93 retains the platform counterpart. This is central policy/instruction delivery, not imposed identical category sets or proof of every local/UI adoption.

## How

Use immutable owning sources and the existing registered synchronizer. The
[batch receipt](../rollouts/second_ten_receiving_20261112.json) separates source,
public bytes, original native execution, local controls, documentary delivery
and missing owner/hosted evidence. Published Pytest Receptor 1.2.3 supplies local
test evidence. GH Run Receptor is used before targeted native job/step checks.

## Why

Close only the bounded central decision/receiving conditions. Components keep
implementation, scientific interpretation, publication, runtime adoption and
their exact artifact/platform qualification. A guide copy does not supply them.

## What is measured and what is assumed

Local inert implementation controls and the original native MolSysMT receiving
are independently observed. Numerical/GUI owner totals and private build/closure
claims remain owner-produced evidence, not central reruns. The receipt records
source paths, hashes, commands, failures and the new hosted/delivery observations
when acquired. Missing evidence is not an empty or passing result.

## Alternatives and refuted paths

Do not replace immutable packages, move policy tags, fork provider semantics,
silently upgrade primary clones or activate deferred science. Existing supported
tools and owner contracts are reused; new functionality stays independently
useful within its documented scope. No common all-component scientific gate is
added merely for this guidance.

## Scope and exclusions

Central tooling/policy and selected receiving only. Primary/human work, #82's
prefix pause, #25/#114 deferrals, TopoMT #196 and original publication/recovery
scopes remain. Component source changes require their owner route. The legacy
development prefix is retained while the new named profile is independently
qualified; no global environment migration is performed.

## Acceptance criteria

- Record the concrete source/contract/owner disposition above and its limits.
- Pass the relevant local guard or publish the normative decision named above.
- Receive applicable exact-source hosted steps; distribute common guide bytes
  through the official synchronizer with immutable consumer identities.
- Keep missing owner reviews and actual source-hint repairs open where required.
- Publish meaningful owning handoffs and retire only task-owned unneeded scratch.

## Local implementation issues

Stable owner identities are listed in the outcome and normalized batch receipt;
no owner issue is closed merely because central source or guidance is delivered.

## Dependencies and risks

Concrete pending owner work is kept explicit. Source publication does not qualify
an installed/public pair, arbitrary future schema, all platforms/minors, complete
scientific semantics or live prefix migration.

`molsyssuite@uibcdf_3.14` transitional environment. No shared package is installed
or replaced. Actual new environment and UML receiving are separately hosted;
